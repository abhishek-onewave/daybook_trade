## 0. MISSION

Build **Daybook**: a personal stock-research web application for exactly one user (Tracy). It has three capabilities, equal in importance:

1. **Ask** — a chat assistant powered by the newest Claude models via the Anthropic API. It must answer with the same quality and style as Claude itself: live web search with citations for news, exact figures from real data feeds, plain English. Critically, it must **already know the whole application's data** — the dashboard state, the watchlist, live quotes, cached news, and the user's real Tastytrade portfolio — injected automatically on every message. The user never pastes data in.
2. **Live market awareness** — real-time-grade quotes (Alpaca free tier), a continuously refreshed news feed tagged to the watchlist with sentiment and a one-line "why it matters," and a live stats page.
3. **Portfolio intelligence** — a read-only Tastytrade connection that syncs accounts, balances, and positions; a deterministic metrics engine computed in code (never by the LLM); and a Portfolio page. The chat can analyze the portfolio because the portfolio snapshot is in its context.

This is an **advisory research tool. It never places, modifies, or cancels orders. There is no trading capability anywhere in this codebase.**

## 1. NON-NEGOTIABLE GUARDRAILS (check every phase against these)

**G1 — Read-only brokerage.** Only GET endpoints from Tastytrade (accounts, balances, positions, transactions, net-liq history). Never implement, import, or scaffold any order-related endpoint. Add an automated guard: a test that greps the codebase for `orders` POST/PUT/DELETE calls against the Tastytrade base URLs and fails CI if found.

**G2 — Numbers come from data, never from language.** Every price, balance, position value, and P&L shown in the UI or spoken by the assistant must originate from Alpaca, Tastytrade, or the metrics engine — never from a web-search snippet and never generated by the model. The assistant's system prompt (Section 8) enforces this on the LLM side; the tool design enforces it structurally.

**G3 — No investment advice.** The assistant explains, contextualizes, and computes. It never says buy/sell/hold or "you should." If asked, it explains the factors and says deciding is the user's call. Every page footer and the assistant's system prompt carry: *"Daybook explains markets. It doesn't recommend trades."*

**G4 — Citations are mandatory.** Any claim sourced from the web renders with its source link. The citations array from the Anthropic web-search tool is stored with each message and displayed.

**G5 — Timestamps everywhere.** Every data payload carries `as_of`. The UI renders it. Stale data (>2 min for quotes during market hours) is visibly marked "delayed."

**G6 — Say "unavailable," never invent.** If a tool call fails or data is missing, the assistant states that plainly and suggests a refresh. Empty UI states say what's missing. Fabrication is the worst failure mode in this product.

**G7 — Secrets discipline.** All keys live in `.env` (never committed; `.env.example` is committed). Tokens are never logged, never sent to the frontend, never embedded in client code. The Anthropic, Alpaca, and Tastytrade calls happen **only** on the backend.

**G8 — Spend and rate guards.** Web search capped at `max_uses: 3` per assistant turn. News enrichment uses the cheapest model. A per-day request counter (configurable, default 300 assistant turns/day) returns a friendly "daily limit reached" rather than surprise costs. Document setting a billing alert in the Anthropic console in README.

**G9 — Verify against official docs; docs win.** Before coding any external call, check the exact endpoint/params against the official documentation listed in Section 5. If this prompt and the docs disagree, follow the docs and record the deviation in `BUILD_NOTES.md`. Do not invent fields, endpoints, or parameters.

**G10 — Phase gates.** Do not start phase N+1 until phase N's VERIFY block passes with real output. Keep a running `WORKLOG.md` with each gate's evidence (command + actual output).

## 4. MODELS (exact strings — the "latest and best" requirement)

Defined once in `app/config.py`:

- `MODEL_FLAGSHIP = "claude-fable-5"` — Anthropic's newest, top-tier model. Used for: any question that touches the portfolio, multi-step analysis, and when the user's "Answer depth" setting is Deep.
- `MODEL_STANDARD = "claude-sonnet-4-6"` — everyday questions; fast and cost-efficient.
- `MODEL_LIGHT = "claude-haiku-4-5-20251001"` — background news enrichment ("why it matters" lines, sentiment) only.

Routing rule in `chat.py`: portfolio-related or Deep → FLAGSHIP; else STANDARD. Keyword trigger for portfolio-related: the context builder sets a flag when the question mentions portfolio/positions/my account/P&L or when the Portfolio page initiated the chat.

Use **prompt caching** (`cache_control: {"type": "ephemeral"}`) on the static system prompt and tool definitions to cut input cost — the app-state block changes per turn and is not cached. Verify current caching syntax and the current web-search tool version string at https://docs.claude.com before coding (G9). Known-good starting point for the server tool: `{"type": "web_search_20250305", "name": "web_search", "max_uses": 3}` — confirm whether a newer type string exists and prefer it.

## 5. EXTERNAL SERVICES — INTEGRATION SPECS

### 5a. Anthropic API (docs: https://docs.claude.com)
- `POST https://api.anthropic.com/v1/messages` with `x-api-key` + `anthropic-version` headers via the official Python SDK.
- Tools per assistant turn: the server-side `web_search` tool (Anthropic executes searches; response includes citation objects) **plus** the custom client tools in Section 8. Implement the standard tool-use loop: while `stop_reason == "tool_use"`, execute the named local tool, append a `tool_result` block, continue.
- Store: answer text, citations `[{url,title}]`, model used, token usage per turn (for the cost log).

### 5b. Alpaca Market Data — FREE tier (docs: https://docs.alpaca.markets)
What the free plan provides (build within these limits):
- **Real-time via WebSocket, IEX feed only:** `wss://stream.data.alpaca.markets/v2/iex` — one concurrent connection; up to 30 symbols for trades/quotes channels; minute-bar channels unlimited.
- **REST:** latest quotes/trades/snapshots with `feed=iex` (real-time IEX) or `feed=delayed_sip` (15-minute delayed consolidated tape); historical bars (`/v2/stocks/bars`) for sparklines and charts. Rate limit ~200 requests/min.
- Base: `https://data.alpaca.markets`. Useful endpoints: `GET /v2/stocks/snapshots?symbols=...&feed=iex`, `GET /v2/stocks/bars?symbols=...&timeframe=1Min|1Day&...`.
- v1 implementation: **REST snapshot polling every 15s during market hours** for the watchlist + SPY/QQQ/DIA (index proxies). The WebSocket is a Phase-7 upgrade, not required for acceptance. Label IEX-sourced prices "indicative (IEX)" in a tooltip; free tier is IEX, not the consolidated tape.
- Note in README: the $99/mo Algo Trader Plus upgrade path exists for full SIP data; not needed for v1.

### 5c. Tastytrade Open API — READ-ONLY (docs: https://developer.tastytrade.com)
- **Auth: OAuth2 only** (session auth is deprecated). Register an OAuth application in the Tastytrade developer portal to get client id/secret; implement the documented OAuth2 flow (their API guides cover it) with encrypted token storage in the DB and automatic refresh.
- **Sandbox first:** build and pass Phase 4 against the certification/sandbox environment, then flip `TASTYTRADE_ENV=production` for Tracy's real account. Consult the docs' sandbox section for the cert base URL and test-account setup.
- Endpoints to integrate (exact paths per the Open API spec at developer.tastytrade.com — verify before coding, G9): list customer accounts; account **positions**; account **balances**; account **transactions**; **net liquidating value history**. Nothing else. No order endpoints (G1).
- Sync job: pull balances+positions every 5 minutes during market hours and on demand (`POST /api/portfolio/sync`), store snapshots with `as_of`.
- Position marks: prefer Tastytrade-provided mark/close prices from the positions payload; enrich/refresh equity marks from Alpaca when symbols overlap. Options positions render with their instrument-type, symbol, quantity, and mark as provided.

### 5d. News (feed pages)
- Primary poller: Finnhub free tier (60 calls/min) company news for watchlist symbols every 5 min → dedupe by URL/title-hash → tag tickers (watchlist symbol/name match) → enrich each *new* story once with `MODEL_LIGHT`: JSON `{sentiment: bullish|bearish|neutral, why: "<one plain-English sentence>"}` → cache in DB.
- If `FINNHUB_API_KEY` is absent, fall back to a `MODEL_LIGHT` + web_search structured-JSON news scan every 10 min (same schema; must never invent stories — instruction in the job prompt).
- The **chat does not depend on this poller** — it has live web_search; the poller exists so feed pages are fresh without user action.

## 7. BACKEND API CONTRACT (all JSON, all include `as_of` where applicable)

- `GET /api/prices` → `{as_of, quotes:{SYM:{last,change_abs,change_pct,volume}}, indices:{SPY,QQQ,DIA}}`

- `POST /api/portfolio/sync` → pull fresh from Tastytrade
- `GET /api/portfolio/connect` + `GET /api/portfolio/callback` → OAuth2 flow; `DELETE /api/portfolio/connection` → disconnect + wipe tokens
- `POST /api/chat {conversation_id?, message}` → streams or returns `{answer, citations, model, as_of}` and persists both turns; `GET /api/chat/history`
- `GET /api/settings` / `PUT /api/settings`
- `GET /api/health` → checks DB + each upstream (anthropic/alpaca/tastytrade configured? reachable?)

## 8. THE CHAT BRAIN (this is the product — build it exactly)

**Requirement being satisfied:** the assistant must answer with full knowledge of the app — no copy-pasting portfolio data into the chat. Two mechanisms combine:

**(A) Context injection.** `build_context()` assembles, per turn:
```
<app_state as_of="...">
  {"user": {"name": ...},
   "watchlist": [...],
   "quotes": {...latest cached, with as_of...},
   "indices": {...},
   "portfolio": {"connected": true|false, "as_of": ...,
                 "balances": {net_liq, cash, buying_power},
                 "positions": [{symbol, type, qty, avg_open, mark, value, pl_abs, pl_pct, weight_pct}],
                 "metrics": {day_pl_abs, day_pl_pct, top_concentration:[{symbol,weight_pct}x3],
                             allocation_by_type, biggest_mover_today}},
   "recent_news": [top 8 cached: {headline, source, published_at, tickers, sentiment, url}]}
</app_state>
```
Size-cap the block (~4k tokens); truncate news first, then bars. This block is appended to the system prompt each turn (not cached; the static prompt is).

**(B) Tools** (custom, executed by the backend) so the model can pull anything fresher or deeper than the snapshot:
- `get_price(symbols: string[])` → live Alpaca snapshot fetch
- `get_bars(symbol, range)` → history for trend questions
- `get_portfolio()` → force-sync Tastytrade, return fresh snapshot
- `get_transactions(days)` → recent account activity
- `get_news(ticker, limit)` → cached feed items
- plus Anthropic's server-side `web_search` (max_uses 3) for anything on the live web.

**(C) The system prompt for the assistant** (store in `chat.py`; this text is part of the spec):

> You are Daybook, {name}'s personal stock-research assistant, embedded in an app whose live state is provided in <app_state>. That state — quotes, watchlist, news, and the user's real Tastytrade portfolio — is trusted ground truth as of its timestamps; use it directly without asking the user for data. Rules, in priority order:
> 1. Never state a price, balance, position, or P&L that did not come from <app_state> or a tool result. If a number is missing or a tool fails, say so plainly and suggest refreshing — never estimate or invent.
> 2. Web search is for news, events, analyst views, and explanations — never for price levels. If search results contain prices, ignore them in favor of get_price.
> 3. Cite a source for every claim that came from the web. No uncited factual claims about current events.
> 4. Attach the data's "as of" time when quoting figures.
> 5. You explain and analyze; you never recommend buying, selling, holding, or sizing. If asked what to do, lay out the factors and trade-offs and state that the decision is theirs. You cannot place orders and refuse any request to do so.
> 6. Portfolio math (P&L, weights, concentration) comes from the metrics engine in <app_state> — recompute nothing; interpret it. You may combine it with news: e.g., linking today's biggest position move to the story driving it, with a citation.
> 7. Plain English, concise by default; depth per the user's setting. When you don't know, say "I don't know."

**(D) Loop + persistence.** Standard tool loop; append user+assistant messages with citations to DB; send last 12 turns as history; respect the daily cap (G8) with a graceful message.

States everywhere: skeleton shimmer loading, ember-left-border error rows with Retry, honest empty states, "as of" stamps, delayed badges (G5).
